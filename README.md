Themes for Steam's Big Picture / Game Mode UI. Pick Dark or Light and slide to a colour; Steam
changes live as you slide. Save it, export it as a [CSS Loader](https://github.com/DeckThemes/SDH-CssLoader)
theme, and send it to any Steam Deck.

**Made for Steam stable build 1794536281** (November 2026). This is maintained on a best-effort
basis: other Steam builds may work partly or not at all. chroma shows the build you're on at the
bottom of its page.

## What you need

- Steam running in **Big Picture** mode, with its **debugging port turned on** (below). chroma
  talks to Steam through it to show colours live.
- To keep a theme after chroma closes: [Decky Loader](https://decky.xyz) with **CSS Loader**
  (on the Deck: Game Mode, Decky store, CSS Loader). chroma's export writes a CSS Loader theme.

### Turn on Steam's debugging port (once)

- **Steam Deck:** Settings › System › turn on **Developer Mode**. Then Settings › Developer › turn
  on **CEF Remote Debugging**. Restart Steam. If Decky Loader is installed, this is already on.
- **Linux desktop:** run `touch ~/.steam/steam/.cef-enable-remote-debugging`, then restart Steam.

chroma looks for it on ports 8080 and 8081. Until it finds Steam, its page shows these steps.

## Install

- **Steam Deck / any Linux:** download `chroma-<version>.AppImage` from Releases. In Desktop Mode,
  right-click it › Properties › Permissions › tick *Is executable* (or `chmod +x`), then open it.
- **Arch:** `sudo pacman -U chroma-desktop-<version>.pacman`, then run `chroma`.
- **From source:** Node 22+, then `node chroma.mjs` and open http://localhost:7300.

## Use

The usual way: on the Steam Deck in Desktop Mode, open Steam in Big Picture (Steam › View › Big
Picture Mode), then open chroma next to it.

0. **Preview:** while on, Steam shows your pick as you go. Switch it off to stop chroma touching
   Steam (it takes its preview back out).
1. **Mode:** Dark or Light.
2. **Colour:** slide the hue. Steam follows within a fraction of a second.
3. **Save As:** name it and press **Save**. Saved themes are listed under *Saved Themes*; click one
   to bring it back.
4. **Export:** saves, then:
   - writes it into this machine's CSS Loader themes (`~/homebrew/themes/chroma-<name>/`). chroma
     never switches themes on or off: in Game Mode › Quick Access › Decky › CSS Loader, refresh,
     and switch on *chroma: &lt;name&gt;*.
   - writes `~/Downloads/chroma-<name>.zip`, for another machine.

Export doesn't need Steam running.

**chroma's preview sits on top of CSS Loader's themes.** While chroma is open with Preview on,
switching themes in CSS Loader won't show. Switch Preview off, or close chroma (closing its page
or the app takes the preview out of Steam), and CSS Loader's theme shows again.

### Send a theme to another Deck

1. Export, then send `chroma-<name>.zip` from `~/Downloads` (Discord or any chat, email, USB…).
2. On the Deck, in Desktop Mode, extract it into `/home/deck/homebrew/themes/`, so that you have
   `/home/deck/homebrew/themes/chroma-<name>/theme.json`.
3. Back in Game Mode: Quick Access › Decky › CSS Loader, refresh, switch on *chroma: &lt;name&gt;*.

A CSS Loader theme is a folder holding `theme.json` and the theme's CSS. The zip keeps them
together. chroma's own saved-theme `.json` files aren't something CSS Loader can read.

## Dev mode

chroma's page has a **Dev Mode** link (`/dev`): the per-element editor behind the picker. Most people
won't need it. It lists Steam's UI elements one row per element and state, each with its own
colour, plus the palette (a Steam colour → yours, everywhere). It can **trawl** the current
screen (and an open Ctrl+1 / Ctrl+2 menu) for elements it doesn't know yet, and **locate** a row
by outlining it in Steam.

It's built agent-first: every action is a plain HTTP call, so a coding agent (or a script) can
drive it while Steam shows the result. Run `node chroma.mjs` (or the app) and use:

| Call | Does |
|---|---|
| `GET /api/status` | Steam reachable? Big Picture open? Build vs the build chroma was made for. |
| `GET /api/state` | The catalogue's elements (`parts`, with Steam's default colours and how many are on screen) and the dev profile. |
| `POST /api/preview` `{ edits: [{ part, set: { background, color, … } }], followMaster, palette: true }` | Show edits in Steam and save them to the dev profile. |
| `POST /api/trawl` | Scan the current screen for elements not in the catalogue. Nothing is saved. |
| `POST /api/accept` `{ ids }` | Add trawled elements to the catalogue. |
| `POST /api/locate` `{ part, key }` | Outline an element in Steam (`part: null` clears it). |
| `POST /api/remove` `{ part }` | Bin an element. |
| `POST /api/defaults` `{ on }` | Show Steam's own colours while on. |
| `POST /api/preview/clear` | Take chroma's preview out of Steam. |
| `POST /api/export` | Export the dev profile (as above). |
| `GET /api/picker`, `POST /api/picker/preview` / `save` / `export` `{ mode, hue, name }` | The picker. |

Values are colours only (hex, `rgb()`, `rgba()`, `hsl()`…; `blur(Npx)` for the glass).

**About the names.** Element names in dev mode are chroma's, not Steam's. Some were written by
hand from what the element looked like; the rest are pieced together from Steam's minified class
names and a sample of on-screen text. They don't match what Steam calls things in its code, and
they aren't guaranteed to describe the element well. Use **locate** to see what a row is.

| | From source | App |
|---|---|---|

| Catalogue extended by trawls, Steam colour snapshot | `catalog/` | `~/.config/chroma/catalog/` |

## How it works

- **Live preview:** chroma injects one `<style>` into Steam's Big Picture, Ctrl+1 and Ctrl+2 windows
  over the Chrome DevTools Protocol.
- **Palette:** Steam hard-codes its colours, so a theme swaps each of Steam's colours for yours in
  every rule that uses it. That includes near shades, gradients, shadows, animations and colour
  variables. The rules come from a snapshot of Steam's stylesheets (`catalog/<build>.rules.json`),
  topped up whenever chroma sees Steam load more.
- **Picker:** every colour of a template theme (`templates/chroma.json`) is turned around the hue
  wheel in OKLCH, which keeps each colour's lightness, so the template's contrast holds. Dark mode
  lowers the backgrounds' lightness.
- Design notes and decisions: `docs/design.md`.
